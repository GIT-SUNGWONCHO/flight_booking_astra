# 실전 — 전날부터 결제까지

좌석은 **출발 360일 전 09:00(한국 시각)** 에 열린다. 프로그램은 그 40분 전에 스스로 시작해 정각에 주문을 보내고,
좌석을 잡으면 결제창을 열어 둔다. **결제는 사람이 한다.**

## 1. 며칠 전까지

1. [설치](install.md), [설정](config.md), [로그인](login.md)을 마친다.
2. [연습](rehearse.md)을 계정마다 한 번씩 끝까지 해 본다.
3. 그날이 언제인지 본다:

```powershell
.\astra.cmd plan
```

```
잡으려는 편   KE932  FCO → ICN  출발 2027-09-20
좌석 개방     2026-09-25 09:00:00 (한국 시각, 출발 360일 전)
실행하는 날   2026-09-25
시간표        08:20 준비 시작 → 08:38:00 연습 통과 → 08:50:00 로그인 점검 → 09:00:00 발사

  wife-first      자리 9232  프레스티지  09:00:00      개방 800ms 전에 조회를 보낸다 · 계측을 함께 띄운다
  wife-fallback   자리 9243  일반석      개방 3.5초 뒤  wife 의 1순위가 거절됐을 때만 주문한다
  me-first        자리 9242  프레스티지  09:00:00      개방 800ms 전에 조회를 보낸다
  me-fallback     자리 9244  일반석      개방 3.5초 뒤  me 의 1순위가 거절됐을 때만 주문한다
```

## 2. 전날 저녁

```powershell
.\astra.cmd check --online     # 3~4분. 모든 창에서 실제로 로그인·달력까지 가 본다
.\astra.cmd schedule           # 내일 08:20 에 시작하도록 예약한다
```

`check --online` 에 `[ 문제 ]` 가 하나라도 있으면 예약하기 전에 고친다. 가장 흔한 것은 네이버 연동 계정의
`로그인 필요` 다 — `astra login --account <이름>` 으로 다시 로그인한다.

`config/run.json` 의 **`mileage` 가 지금 잔액과 같은지** 대한항공 앱에서 한 번 더 본다.

`schedule` 이 성공하면:

```
[ 확인 ] 예약: Astra-0925-wife-first - 2026-09-25 08:20
[ 확인 ] 예약: Astra-0925-wife-fallback - 2026-09-25 08:20
...
그날 지킬 것
  · PC 를 켜 두고 Windows 에 로그인한 채로 둔다(잠금 화면은 괜찮다, 로그아웃·종료는 안 된다)
  · 08:20 부터는 뜨는 Chrome 창을 건드리지 않는다
  · 알림음이 나면 결제창이 열린 것이다. 그때부터 사람이 결제한다
```

- 예약을 확인하려면 `.\astra.cmd schedule --list`, 취소하려면 `.\astra.cmd schedule --remove`.
- **예약한 뒤에 `config/run.json` 을 고치면 반영되지 않는다.** 예약할 때의 값이 그대로 실행된다. 고쳤으면
  `schedule --remove` 뒤 다시 `schedule` 한다.
- PC 를 [절전하지 않게](install.md#4-pc-설정--실전-날-아침에-pc-가-깨어-있어야-한다) 해 두고, 스피커를 켜 둔다(알림음).
- 결제에 쓸 휴대폰(카드 앱)을 충전해 PC 옆에 둔다.

## 3. 그날 아침 — 프로그램이 하는 일

사람이 할 일은 **08:55 쯤 PC 앞에 앉는 것**뿐이다. 창을 건드리지 않고 지켜본다.

| 시각 | 프로그램이 하는 일 | 콘솔에 나오는 말 |
|---|---|---|
| 08:20 | 실행마다 검은 콘솔 창이 하나씩 뜬다. 전용 Chrome 을 새로 띄우고 로그인해 달력을 연다 | `달력 도착` |
| | 캡처 날짜를 고른다(달력에서 일반석이 남은 가장 가까운 앞 날짜) | `캡처 날짜 자동 선택: …` |
| 08:38 | **연습 통과**: 캡처 날짜로 사이트를 승객 확인까지 한 번 가 본다. 이때 사이트가 보내려는 주문 요청은 막는다 | `준비 통과 결과: {…}` |
| | 달력으로 돌아와 발사 준비가 됐는지 점검한다 | `[arm] 점검 통과` |
| 08:50 | 로그인이 살아 있는지 다시 본다. 문제면 08:52 전까지 처음부터 다시 준비한다 | `[health] 점검 통과` |
| 08:59 | 인터넷 시각 서버와 견줘 PC 시계를 다시 맞춘다 | `시계 보정(최종)` |
| 08:59:59.2 | **발사**: 목표 날짜를 조회한다(개방 0.8초 전에 보낸 조회가 좌석을 받아 온다) | `T0 발사` |
| ~09:00:01 | 조회 응답 → 운임 요청 → 응답 | `조회#1 … 판정=selected`, `운임 … 판정=validated` |
| ~09:00:02 | **주문을 한 번 보낸다** | |
| ~09:00:09 | 주문 응답. 좌석을 잡았으면 그 주문을 화면에 넘겨 동의·마일리지·결제수단까지 누른다 | `주문 … 판정=order-recorded` |
| ~09:00:30 | **결제창이 열리고 알림음이 울린다** | `[사용자 차례] …` |

준비 단계에서 실패하면(연습 통과가 끝까지 못 가는 등) 스스로 Chrome 을 다시 띄워 두 번까지 더 해 본다.
08:52 이 지나면 더 준비하지 않는다 — 덜 된 준비로 정각에 쏘지 않기 위해서다.

대체 실행(`-fallback`)은 같은 일을 3.5초 늦게 한다. 운임까지 끝내 놓고 1순위의 결과를 기다렸다가,
1순위가 거절됐을 때만 주문한다.

## 4. 결과 보기

```powershell
.\astra.cmd status
```

```
2026-09-25 · KE932 FCO→ICN 2027-09-20
  ✔ wife     프레스티지  (자리 9232)  좌석을 잡았다. 결제창이 열려 있다 - 직접 결제한다
  – wife     일반석      (자리 9243)  1순위가 좌석을 잡아서 주문하지 않았다(정상)
  ✘ me       프레스티지  (자리 9242)  주문이 거절됐다. 좌석이 먼저 팔렸다
  ✔ me       일반석      (자리 9244)  좌석을 잡았다. 결제창이 열려 있다 - 직접 결제한다
```

| 표시 | 뜻 | 할 일 |
|---|---|---|
| ✔ 좌석을 잡았다. 결제창이 열려 있다 | 예약이 생겼고 결제만 남았다 | **지금 결제한다**(§5) |
| ✔ 좌석을 잡았다. 대한항공 결제 화면이 열려 있다 | `payment` 가 `manual` 이다. 결제수단을 고를 차례다 | **결제수단을 고르고 결제한다**(§5) |
| ✔ 좌석을 잡았다. 결제창은 열지 못했다 | 예약은 생겼는데 화면이 결제까지 못 갔다 | 대한항공 누리집·앱 → 예약 조회에서 그 예약을 찾아 결제한다 |
| ✘ 주문이 거절됐다 | 다른 사람이 먼저 잡았다. 프로그램 고장이 아니다 | 대체가 있으면 그 줄을 본다. 없으면 끝 |
| – 1순위가 좌석을 잡아서 주문하지 않았다 | 대체가 할 일이 없었다 | 없음 |
| ? 결과를 확인하지 못했다 | 주문은 나갔는데 응답을 못 읽었다 | 대한항공 예약 조회에서 예약이 생겼는지 직접 본다 |
| ✘ … 발사하지 못했다 | 준비가 끝나지 않았다 | 콘솔 로그의 마지막 줄을 [문제 해결](troubleshooting.md)에서 찾는다 |
| … 진행 중이다 | 아직 돌고 있다 | 기다린다 |

거절된 실행의 콘솔 창은 `summary=… exit=종료` 라고 쓰고 입력을 기다린다. `exit` 를 치거나 창을 닫으면 된다.

## 5. 결제 — 사람이 한다

**좌석은 결제해야 내 것이 된다.** 결제하지 않으면 대한항공이 푼다. 2026-09 에 본 보유 시간은 10~32분으로
제각각이었다. **알림음이 나면 바로 결제한다.**

어디까지 해 주는지는 설정의 [`payment`](config.md#17-payment--좌석을-잡은-뒤-어디까지-해-줄지)가 정한다.
어느 쪽이든 결제창 안에서는 프로그램이 아무것도 누르지 않는다.

**`"payment": "auto"`** — 정해진 결제수단의 결제창까지 열어 준다.

| 노선 | 프로그램이 고르는 결제수단 | 열리는 창 |
|---|---|---|
| 한국 **도착**(예: FCO→ICN) | 한국발행 신용/체크카드 → **현대카드** | 현대카드 인증 창(앱카드·PIN 선택). 여기서부터 사람이 한다 |
| 한국 **출발**(예: ICN→CDG) | **네이버페이** | 네이버페이 결제창 |

**`"payment": "manual"`** — 약관 동의와 마일리지 적용까지 해 놓고 멈춘다. 콘솔에 이렇게 나오고 알림음이 울린다:

```
[사용자 차례] 좌석을 잡았다. 자리 9232 의 대한항공 결제 화면에서 결제수단을 고르고 결제하기를 누른다.
```

그 Chrome 창(제목이 `[ASTRA · 9232]` 로 시작한다. 다른 창 뒤에 있으면 작업 표시줄에서 연다)의 결제 화면에서
내 결제수단을 고르고 [결제하기]를 누른다.

현대카드·네이버페이를 쓰지 않는데 `"auto"` 로 돌렸다면: 뜬 결제창을 닫고, 대한항공 화면에서 결제수단을 바꿔
직접 [결제하기]를 누른다. 화면이 넘어가 버렸으면 대한항공 누리집·앱 → 예약 조회에서 그 예약을 찾아 결제한다.

좌석은 이미 잡혀 있으므로 서두르되 당황할 필요는 없다. 마일리지와 세금(현금)이 함께 빠진다.
참고로 본 값은 [설정 §1.2](config.md#12-accounts--누가-무엇을-잡나)에 있다.

## 6. 끝난 뒤

- 콘솔 창과 Chrome 창을 닫는다.
- 예약(작업 스케줄러)은 한 번 실행되고 끝난다. 목록에서 지우려면 `.\astra.cmd schedule --remove`.
- 기록은 `dev-shots/` 에 남는다. 읽는 법은 [증거 견본](../samples/README.md).

## 7. 못 잡았을 때 — 다시 시도

- **다음 날 다른 날짜를 노린다**: `config/run.json` 의 `trip.date` 를 바꾸고 `schedule` 한다. 어제의 기록은
  프로그램이 스스로 치운다. 따로 할 일이 없다.
- **같은 날 한 번 더**: 프로그램은 12시간 안에 주문을 보낸 자리에서 또 주문하지 않는다. 같은 주문이 두 번 나가
  좌석이 둘 잡히는 것을 막기 위해서다. 이렇게 말하고 멈춘다:

  ```
  **새 주문을 보내지 않는다.**
    주문이 거절됐다(2026-09-25 09:00). 좌석은 잡히지 않았다.
    같은 주문을 또 보내면 좌석이 두 개 잡힐 수 있어 여기서 멈춘다.
    그래도 다시 보내려면 --again 을 붙여 실행한다. 이 기록은 12시간 뒤 자동으로 정리된다.
  ```

  앞선 결과를 확인했고(거절이었거나, 예약 조회에 없다) 그래도 다시 보내려면:

  ```powershell
  .\astra.cmd run --again
  ```

  `run` 은 예약 없이 지금 바로 시작한다(오늘 발사 시각 12분 전까지). **"결과를 확인하지 못했다"였다면 먼저 예약 조회를 본다.**
  잡혀 있는데 또 보내면 좌석이 하나 더 잡힌다.

## 8. 하지 말 것

- 08:20~09:01 사이에 전용 Chrome 창을 클릭·스크롤·크기 조절하지 않는다. 화면을 가리는 것은 괜찮다.
- 같은 시간에 휴대폰 앱이나 다른 PC 로 같은 계정의 같은 편을 잡으려 하지 않는다. 서로의 좌석을 뺏는다.
- 08:20 이후에 `astra login`·`astra check --online`·`astra rehearse` 를 돌리지 않는다. 같은 창을 쓴다.
- 결제창에서 프로그램이 대신 눌러 주길 기다리지 않는다. 누르지 않는다.
