# 옛 브라우저 매크로 — 화면을 대신 눌러 주는 방식

**지금 쓰는 예매 프로그램(`astra`)과 다른 것이다.** `astra` 가 나오기 전(2026-08 ~ 09-12)에 쓰던 방식으로,
대한항공 화면 위에 패널을 띄우고 **사람이 한 번 눌러 본 순서를 정각에 그대로 다시 눌러 준다.**

| | `astra` (요청을 직접 보냄) | 이 매크로 (화면을 누름) |
|---|---|---|
| 주문이 나가는 시각 | 개방 2~3초 뒤 | 개방 13초 뒤에도 둘째 단계였다(2026-09-12) |
| 준비 | 설정 파일 하나 | 브라우저에 스크립트 설치, 단계 녹화 확인 |
| 사이트 화면이 바뀌면 | 준비 단계(연습 통과)가 영향받는다 | 녹화를 다시 해야 한다 |
| 언제 쓰나 | 평소 | `astra` 의 요청 방식이 막혔을 때, 또는 **개방 경쟁이 아닌 예매를 손 안 대고 끝까지 하고 싶을 때** |

남겨 둔 까닭: 서버가 요청 재전송을 막는 날이 오면 화면을 누르는 방식만 남는다. 그리고 매진 경쟁이 없는 좌석이라면
이것만으로도 충분하다. **2026-09-12 이후 실사이트에서 돌리지 않았다. 다시 쓰려면 §4 의 연습부터 한다.**

## 1. 무엇으로 이루어져 있나

| 부분 | 위치 | 하는 일 |
|---|---|---|
| 페이지 스크립트(원본) | `ke_award/util.js` `probe.js` `recorder.js` `editor.js` `hud.js` `steps.json` | 패널, 녹화·재생, 정시 발사 |
| 페이지 스크립트(빌드 결과) | `userscript/ke-award-macro.user.js` | 위를 한 파일로 묶은 것. **브라우저에 넣는 것은 이 파일**이다 |
| 실행기 | [`macro/`](../../macro/README.md) | 전용 Chrome 에 스크립트를 넣고 준비·점검·기록을 하는 파이썬 프로그램(§6) |

빌드 결과는 저장소에 들어 있으므로 원본을 고치지 않았으면 다시 만들 필요가 없다. 고쳤으면 `node build.mjs`
(Node.js 필요).

## 2. 설치 — 평소 쓰는 Chrome 에 넣기

1. Chrome 에 확장 프로그램 [Tampermonkey](https://www.tampermonkey.net/) 를 설치한다.
2. Tampermonkey 대시보드 → **새 스크립트** → 안의 내용을 다 지우고 `userscript/ke-award-macro.user.js` 의 내용을
   통째로 붙여 넣는다 → 저장.
3. Chrome 확장 프로그램 관리에서 Tampermonkey 의 "사용자 스크립트 허용"(개발자 모드)을 켠다.
4. koreanair.com 에 들어가면 오른쪽 위에 **KE 마일리지 예매 보조** 패널이 뜬다. 제목 옆 `v1.xxx` 가 넣은 빌드다.

패널이 안 뜨면: 스크립트가 켜져 있는지, 주소가 koreanair.com 인지 본다. 패널은 제목을 끌어 옮길 수 있다.

## 3. 패널

바로 보이는 것:

| 항목 | 하는 일 |
|---|---|
| 시계 · 카운트다운 | 보정한 한국 시각과 발사까지 남은 시간 |
| **발사 시각** | 매크로가 움직일 시각. `09:00` 처럼 넣으면 오늘(지났으면 내일) 그 시각 |
| **좌석 등급** | `일반석`(연습) / `프레스티지`(실전). 좌석 단계가 이 등급의 칸을 찾는다 |
| **목표 날짜** | `09-20` 처럼. 달력에서 이 날짜를 고른다. 아직 안 열렸으면 열릴 때까지 새로고침하며 기다린다. 비우면 가장 나중에 열린 날 |
| **결제하기까지 자동** | 꺼져 있으면(기본) [결제하기] 앞에서 멈춘다. 켜면 [결제하기]까지 눌러 결제창을 띄운다. 결제창 안은 누르지 않는다 |
| **연습 (10초 뒤 발사)** | 발사 시각을 10초 뒤로 잡고 새로고침부터 전 과정을 그대로 해 본다 |
| **▶ 대기 시작** | 발사 시각에 정시 발사한다. 다시 누르면 정지 |
| 빨간 안내 | 창이 좁다, 탭이 뒤에 있다 같은 경고 |

**▸ 고급 설정 펴기** 를 누르면 나오는 것(평소에는 건드리지 않는다):

| 항목 | 하는 일 |
|---|---|
| 선발사(ms) | 발사 시각보다 얼마나 먼저 새로고침을 시작할지. 기본 2500(09:00 이면 08:59:57.5). 새로고침 뒤 달력 요청이 나가기까지 4초쯤 걸리기 때문이다 |
| 시각 동기 | 서버 시각에 맞춰 PC 시계 오차를 다시 잰다 |
| 시작 화면 | `달력`(기본, 검증됨) / `조회 화면`(실험 중) |
| 조회 응답 | 방금 본 좌석 조회 응답을 요약해 보여 준다(좌석 수 조사용) |
| ● 녹화 · ▶ 재생 · 삭제 | 단계 녹화, 지금 화면에서 바로 재생, 내장 단계로 되돌리기 |
| 단계 편집 | 단계 삭제·순서 바꾸기·끼워 넣기 |
| 내보내기 | 녹화한 단계를 `ke_award/steps.json` 에 넣을 모양으로 뽑는다 |

## 4. 처음 쓸 때 — 반드시 연습부터

스크립트 안에는 2026-08-21 에 녹화한 **17단계**가 들어 있다: 날짜 → 검색 → 좌석 → 통화 → 다음 → 승객 확인 →
연락처 확인 → 동의·아래로 스크롤·확인(두 번) → 마일리지 적용 → 결제수단 → 결제하기. **사이트 화면이 바뀌었으면
중간에 멈춘다.** 그래서:

1. 로그인하고, 마일리지 예매로 노선을 넣어 **달력 화면**까지 간다. 창은 넓게(1400px 이상) 둔다.
2. 패널에서 등급을 `일반석`, 목표 날짜를 **이미 열려 있고 좌석이 남은 날**로 넣는다. "결제하기까지 자동"은 꺼 둔다.
3. **연습 (10초 뒤 발사)** 를 누른다. 10초 뒤 새로고침되고 단계가 저절로 흘러간다.
4. [결제하기] 앞에서 "재생 중지 - 결제 직전"으로 멈추면 성공이다. 그대로 창을 닫는다(결제하지 않으면 좌석은 풀린다).

도중에 멈추면 패널이 몇 번째 단계에서 왜 멈췄는지 적는다. 대부분 그 단계의 버튼 모양·글자가 바뀐 것이다 → §5.

## 5. 단계를 다시 녹화하기

1. 달력 화면에서 고급 설정을 펴고 **삭제**(내장 단계로 되돌림) 또는 그대로 **● 녹화**.
2. 평소 예매하듯 끝까지 직접 누른다(패널 자체를 누르는 것은 기록되지 않는다). [결제하기]는 누르지 않는다.
3. **● 녹화**를 다시 눌러 끝낸다. **단계 편집**에서 괜히 눌린 단계를 지우고 빠진 단계를 끼워 넣는다.
   - 날짜처럼 글자가 매일 바뀌는 버튼은 **고정**을 켠다(글자를 무시하고 자리로 찾는다).
   - 날짜와 좌석 단계는 녹화한 그 칸이 아니라 **그때 화면에서 다시 찾는다**(목표 날짜·좌석 등급 기준).
4. §4 의 연습으로 확인한다.
5. 다른 PC 에서도 쓰려면 **내보내기** → `ke_award/steps.json` 에 덮어쓰기 → `node build.mjs` → 새 빌드를 다시 붙여 넣는다.
   브라우저에 직접 녹화한 것이 있으면 그쪽이 우선한다.

## 6. 실전에서 쓰는 법

1. 08:50 쯤 로그인해 달력 화면을 띄워 둔다. **창을 넓게, 최소화하지 않고, 그 탭을 앞에 둔다.**
2. 발사 시각 `09:00`, 등급, 목표 날짜를 넣는다. "결제하기까지 자동"을 켤지 정한다.
3. **▶ 대기 시작**. PC 가 잠들지 않게 한다(패널이 화면 꺼짐을 막으려 하지만 절전 설정은 직접 본다).
4. 정각에 새로고침이 걸리고 단계가 흘러간다. 멈추면 알림음이 난다. 결제는 직접 한다.

알아 둘 것:

- **창 너비가 가장 흔한 실패 원인이다.** 화면이 좁아지면 모바일 배치로 바뀌어 버튼 자리와 글자가 달라진다.
- 동의 버튼은 다시 누르면 꺼진다. 매크로는 켜져 있는지 읽고 누른다. 사람이 중간에 눌러 주면 오히려 꺼질 수 있다.
- 통화를 원화로 바꾸면 화면이 달력으로 되돌아간다. 매크로가 그 뒤 날짜·좌석을 다시 고른다.
- 재생 중 달력이 아닌 화면으로 튕기면(로그인 풀림, 사이트 안내) 누르지 않고 멈춘다.
- 약한 PC 나 느린 회선에서는 선발사 2500 이 맞지 않을 수 있다. 완료 문구의 "재고침 N회"가 0 이 아니면 너무 이른 것이다.

## 7. 전용 Chrome 과 실행기 (`macro/`)

`macro/` 의 파이썬 실행기는 `astra` 와 같은 전용 Chrome(자리 9232, 계측 9233)에 스크립트를 넣고, 08:20 준비와
08:50 점검과 기록을 대신 해 주던 것이다. **이 저장소의 2026-09 일정표([config/test_calendar.json](../../config/test_calendar.json))를
읽도록 돼 있어, 다른 노선·날짜로 쓰려면 그 파일부터 고쳐야 한다.** 손으로 §6 처럼 쓰는 편이 간단하다.

| 명령 | 하는 일 | 주의 |
|---|---|---|
| `python dev\test_calendar.py --day 2026-09-25` | 그날의 노선·편·출발일을 일정표에서 본다 | |
| `python macro\prepare_day.py --day <날짜>` | 08:20 준비: 로그인·달력·통화, 패널에 목표 표시, 대기 기록 시작 | `--preview`·`--rehearsal` 은 **실제 예약(미결제)을 만들 수 있다** |
| `python macro\check_day.py --day <날짜>` | 08:50 읽기 전용 점검 | 아무것도 바꾸지 않는다 |
| `python macro\manual_booking.py --day <날짜>` | 사람이 패널에서 대기 시작을 누르는 동안 스크립트 유지와 기록 | 정시 발사는 사람이 누른 패널이 한다 |
| `python macro\rehearse.py` | 그날 돌 것을 통째로 미리 돌려 본다 | `macro\day.ps1` 의 노선을 쓴다 |

(`python` 은 `.venv\Scripts\python.exe`.) 자세한 조건과 그때의 실측은 [브라우저 예매 명세](../spec/browser-booking.md).

`astra` 의 전용 Chrome 창에는 이 패널이 뜨지 않는다. `astra` 는 화면을 누르지 않으므로 패널과 재생 엔진을 싣지 않는다
(로그인 준비가 쓰는 도우미만 싣는다). 두 방식을 같은 창에서 섞어 쓰지 않는다.

## 8. 시험

사이트에 접속하지 않고, 가짜 화면(픽스처)으로 패널·녹화·재생을 시험한다.

```powershell
.\.venv\Scripts\python.exe run_tests.py engine     # 페이지 스크립트 40개 파일, 3분
.\.venv\Scripts\python.exe run_tests.py macro      # 실행기 9개 파일
```

원본(`ke_award/*.js`)을 고쳤으면 `node build.mjs` 뒤에 돌린다. 급하면 핵심만:
`run_tests.py engine -k hud -k parity -k skipcal -k deadclick -k twoagree -k pagewait -k currency`.
