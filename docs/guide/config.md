# 설정 — `config/run.json` 과 `.env`

바꿀 파일은 둘뿐이다. 둘 다 메모장으로 연다. `astra setup` 이 본보기에서 만들어 준다.

| 파일 | 무엇을 적나 | 저장소에 올라가나 |
|---|---|---|
| `config/run.json` | 잡으려는 편, 계정, 마일리지, 시각 | 아니다(내 것만 남는다) |
| `.env` | 대한항공 아이디·비밀번호 | **절대 아니다** |

고친 뒤에는 `astra check` 로 확인한다. 틀린 곳이 있으면 어디를 어떻게 고칠지 한 번에 알려 준다.

## 1. `config/run.json`

본보기([config/run.example.json](../../config/run.example.json))는 2026-09-25 에 두 계정이 좌석을 잡은 설정 그대로다.
`_` 로 시작하는 줄은 설명이다. 지워도 되고 그대로 둬도 된다.

```json
{
  "trip": {
    "origin": "FCO",
    "destination": "ICN",
    "flight": "932",
    "date": "2027-09-20",
    "captureDate": "auto"
  },
  "accounts": [
    { "name": "wife", "login": "skypass", "mileage": 100000, "first": "prestige", "fallback": "economy" },
    { "name": "me",   "login": "naver",   "mileage": 65000,  "first": "prestige", "fallback": "economy" }
  ],
  "observer": "me",
  "times":  { "open": "09:00:00", "start": "08:20", "capture": "08:38:00", "health": "08:50:00", "lastPrepare": "08:52:00" },
  "tuning": { "preFireMs": 800, "fallbackDelayMs": 3500, "fallbackWaitSeconds": 5 }
}
```

### 1.1 `trip` — 잡으려는 편

| 항목 | 뜻 | 적는 법 |
|---|---|---|
| `origin` · `destination` | 출발·도착 공항 | 세 글자 대문자. 로마 `FCO`, 파리 `CDG`, 런던 `LHR`, 인천 `ICN` |
| `flight` | 편명 | **숫자만.** KE932 → `"932"` |
| `date` | 출발일 | `"2027-09-20"` |
| `captureDate` | 연습 통과에 쓸 날짜 | 보통 `"auto"`. 아래 참고 |

- **한 번에 편 하나만** 잡는다. 대한항공이 직접 띄우는 편(KE932·KE902·KE908)으로만 해 봤다.
  다른 항공사가 띄우는 공동운항편(KE5902 같은 네 자리)은 해 보지 않았다.
- **그 요일에 그 편이 뜨는지 먼저 확인한다.** 대한항공 누리집에서 이미 열린 같은 요일을 조회해 본다.
  예: 일요일 CDG→ICN 은 대한항공 운항편이 없어 2026-09-24 에 런던(LHR, KE908)으로 바꿨다([9/24 결과](../results/2026-09-24.md)).
- **좌석은 출발 360일 전 09:00(한국 시각)에 열린다.** 2027-09-20 출발이면 2026-09-25 09:00 이다.
  `astra plan` 이 날짜를 계산해 보여 준다.

`captureDate` 는 **이미 열려 있고 일반석이 남은 다른 날짜**다. 프로그램은 실전 20분 전에 이 날짜로 사이트를 끝까지 한 번
가 보고(주문은 막은 채), 그때 얻은 요청 모양으로 09:00 에 진짜 요청을 보낸다. `"auto"` 로 두면 달력을 읽어
목표보다 앞선 날 중 일반석이 있는 가장 가까운 날을 고른다. 직접 정하고 싶을 때만 날짜를 적는다.

### 1.2 `accounts` — 누가 무엇을 잡나

계정은 **한 개 또는 두 개**다. 위에 적은 것이 첫째 계정이다.

| 항목 | 뜻 |
|---|---|
| `name` | 구분용 이름. 영문·숫자로 아무렇게나(`wife`, `me`, `dad` …). 파일 이름과 화면에만 쓰인다. 실제 아이디가 아니다 |
| `login` | `"skypass"` = 대한항공 아이디·비밀번호로 로그인(프로그램이 `.env` 를 읽어 스스로 한다). `"naver"` = 네이버 연동(창에서 사람이 한 번 로그인) |
| `mileage` | **그 계정의 지금 마일리지 잔액**. 아래 참고 |
| `first` | 먼저 노릴 등급. `"prestige"` 또는 `"economy"` |
| `fallback` | `first` 가 거절됐을 때 잡을 등급. 필요 없으면 `null` |

**`mileage` 는 왜 적나.** 프로그램은 필요 마일리지가 이 숫자보다 크면 주문을 보내지 않는다. 잔액이 모자란 채로
주문했다가 좌석만 묶이는 것을 막으려는 것이다. 사이트에서 읽어 오지 않으므로 **대한항공 앱·누리집의 "사용 가능 마일리지"를
보고 직접 적는다.**

- 넉넉하게 적으면 안 된다. 실제 잔액을 적는다.
- 참고로 본 값(유럽 → 한국 편도, 2026-09): 프레스티지 62,500 / 일반석 35,000(평수기), 일반석 52,500(성수기).
  세금·유류할증료는 따로 현금으로 낸다(프레스티지 685,700원, 일반석 374,700원을 봤다). 값은 노선·시기마다 다르다.
- 실행이 시작할 때의 값으로 본다. 그 사이 다른 예매로 마일리지가 줄었으면 실전 전에 고쳐 적는다.
- 한 계정의 1순위와 대체는 같은 잔액을 본다. 둘이 함께 주문되는 일은 없게 돼 있으므로(아래) 따로 나누지 않는다.

**`fallback` 은 어떻게 도나.** 같은 계정으로 브라우저를 하나 더 띄워 대체 등급을 준비해 둔다. 그 실행은 조회와 운임까지
끝내 놓고 **주문 직전에만** 1순위의 결과를 본다.

- 1순위가 좌석을 잡았다 → 대체는 주문하지 않는다.
- 1순위가 "좌석 없음"으로 거절됐다 → 대체가 곧바로 주문한다(2026-09-25 에 거절 0.81초 뒤 주문).
- 1순위의 결과가 애매하거나 `fallbackWaitSeconds` 안에 안 온다 → 대체는 주문하지 않는다. 두 좌석이 잡히는 쪽보다
  하나도 안 잡히는 쪽을 택한다.

### 1.3 `observer` — 계측(없어도 된다)

`accounts` 의 `name` 하나를 적거나 `null`. 계측은 좌석이 몇 석이었고 언제 줄었는지를 **기록만** 한다.
예매와 따로 돌고, 실패해도 예매는 계속한다. 왜 못 잡았는지 나중에 따져 보려면 켜 둔다.

### 1.4 `times` 와 `tuning` — 보통 그대로 둔다

| 항목 | 뜻 | 본보기 값 |
|---|---|---|
| `times.open` | 좌석이 열리는 시각. 대한항공 마일리지 좌석은 09:00:00 | `09:00:00` |
| `times.start` | PC 가 준비를 시작하는 시각 | `08:20` |
| `times.capture` | 연습 통과를 시작하는 시각 | `08:38:00` |
| `times.health` | 로그인이 살아 있는지 다시 보는 시각 | `08:50:00` |
| `times.lastPrepare` | 이 시각 뒤에는 다시 준비하지 않는다 | `08:52:00` |
| `tuning.preFireMs` | 개방 몇 ms **전**에 조회를 보낼지. 800 이면 08:59:59.200 | `800` |
| `tuning.fallbackDelayMs` | 대체 실행이 개방 몇 ms **뒤**에 조회를 보낼지 | `3500` |
| `tuning.fallbackWaitSeconds` | 대체 실행이 1순위 결과를 기다리는 최대 초 | `5` |

왜 이 값인지는 [왜 이렇게 만들었나](why.md)에 있다. 줄여서 좋아진다는 근거가 없으면 바꾸지 않는다.
특히 `start` 를 08:12 보다 앞당기면 안 된다 — 로그인 토큰이 약 57분이라 09:05 전에 끊긴다.

### 1.5 계정 구성 본보기

**계정 하나, 프레스티지만**

```json
"accounts": [ { "name": "me", "login": "skypass", "mileage": 70000, "first": "prestige", "fallback": null } ],
"observer": null
```

**계정 하나, 프레스티지가 안 되면 일반석**

```json
"accounts": [ { "name": "me", "login": "naver", "mileage": 70000, "first": "prestige", "fallback": "economy" } ],
"observer": "me"
```

**계정 둘, 둘 다 스카이패스 아이디**(둘째의 아이디·비밀번호는 `.env` 의 `KE_SKYPASS_ID_2`·`KE_SKYPASS_PW_2`)

```json
"accounts": [
  { "name": "a", "login": "skypass", "mileage": 100000, "first": "prestige", "fallback": "economy" },
  { "name": "b", "login": "skypass", "mileage": 65000,  "first": "prestige", "fallback": "economy" }
]
```

### 1.6 브라우저 자리

프로그램은 계정·쓰임마다 전용 Chrome 을 하나씩 띄운다. 평소 쓰는 Chrome 과 섞이지 않는다.
자리는 고정이고 설정에서 바꾸지 않는다.

| 자리(포트) | 쓰임 | 로그인이 저장되는 폴더 |
|---|---|---|
| 9232 | 첫째 계정 1순위 | `.debug-profile` |
| 9243 | 첫째 계정 대체 | `.debug-profile3` |
| 9242 | 둘째 계정 1순위 | `.api-profile` |
| 9244 | 둘째 계정 대체 | `.api-profile2` |
| 9233 | 계측 | `.debug-profile2` |

이 폴더들에는 로그인된 세션이 들어 있다. **남에게 보내지 않는다.**

## 2. `.env` — 아이디와 비밀번호

`login` 이 `"skypass"` 인 계정만 채운다. `"naver"` 인 계정은 여기 적을 것이 없다.

```
KE_SKYPASS_ID=          ← 첫째 계정의 대한항공 아이디 또는 스카이패스 번호
KE_SKYPASS_PW=          ← 그 비밀번호
KE_LOGIN_TAB=           ← 보통 비운다

KE_SKYPASS_ID_2=        ← 둘째 계정이 skypass 일 때만
KE_SKYPASS_PW_2=
KE_LOGIN_TAB_2=
```

- `=` 뒤에 띄어쓰기 없이 적는다. 따옴표는 필요 없다.
- `KE_LOGIN_TAB`: 대한항공 로그인 화면에는 **아이디 / 스카이패스 번호** 탭이 있다. 비워 두면 값이 숫자뿐일 때
  스카이패스 번호 탭으로, 아니면 아이디 탭으로 넣는다. "일치하는 회원정보가 없습니다"가 뜰 때만 `아이디` 또는 `스카이패스` 를 적는다.
- **비밀번호를 채팅창·메신저·AI 도우미 대화에 붙여 넣지 않는다.** 이 파일에만 둔다.
- 이 폴더를 통째로 남에게 줄 때는 `.env` 와 위 표의 로그인 폴더 다섯 개를 빼고 준다.

프로그램은 `.env` 의 값을 화면이나 기록에 내보내지 않는다. `astra check` 도 "채워져 있다 / 비어 있다"만 말한다.
