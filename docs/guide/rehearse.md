# 연습 — 실전 전에 한 번은 끝까지 해 본다

실전은 하루에 한 번, 몇 초 만에 끝난다. 그날 처음 돌려 보면 안 된다. **이미 열려 있는 날짜**로 같은 순서를 끝까지
해 보는 것이 연습이다.

```powershell
.\astra.cmd rehearse
```

## 1. 무슨 일이 일어나나

```
연습: 계정 wife 로 KE932 FCO→ICN 2027-09-13 일반석을 끝까지 잡아 본다.
  · 실전과 같은 순서다: 로그인 → 연습 통과 → 대기 → 발사 → 주문 → 결제창
  · 약 12분 걸린다. 그동안 그 Chrome 창을 건드리지 않는다
  · **실제 예약(미결제)이 1건 생긴다.** 결제창에서 결제하지 않으면 스스로 풀린다
  · 결제창이 뜨면 그냥 닫는다. 결제 버튼은 누르지 않는다
계속하려면 yes 를 입력한다:
```

`yes` 를 치면 시작한다.

- **진짜 예약이 하나 생긴다.** 좌석을 잡는 요청까지 실제로 보내기 때문이다. 결제하지 않으면 대한항공이 스스로 푼다.
  2026-09 에 본 시간은 10분·26분·30분·32분으로 제각각이었고, 한 번은 5시간 넘게 남아 있었다. 마일리지는 결제 전에는 빠지지 않는다.
- **일반석으로 한다.** 프레스티지는 좌석이 한두 석이라 연습으로 묶어 두면 그동안 남이 못 산다.
- 연습 날짜는 프로그램이 고른다: 목표와 같은 요일이면서 이미 열려 있는 가장 가까운 날. 바꾸려면 `--date 2027-09-13`.
  그 날짜에 일반석이 남아 있어야 한다(대한항공 누리집에서 확인하거나 `astra check --online` 의 달력 결과를 본다).
- 계정은 첫째 계정이다. 다른 계정으로 하려면 `--account me`. **계정마다 한 번씩 해 본다.**

## 2. 성공하면

콘솔에 이런 줄이 차례로 나온다([전체 견본](../samples/console-1-success.log)):

```
달력 도착
캡처 날짜 자동 선택: 2027-09-11 (일반석 있음)
준비 통과 결과: {... 'contact': True, 'orderRequests': {'seen': 1, 'blocked': 1, 'unblocked': 0} ...}
[arm] 점검 통과
T0 발사
조회#1 status=200 ... 판정=selected
운임 status=200 ... 판정=validated
주문 status=200 ... 판정=order-recorded
[사용자 차례] 현대카드 창이 열렸다. 앱카드/PIN 인증과 최종 결제는 사용자가 한다.
[ 확인 ] 연습이 끝까지 갔다. 결제창이 열려 있으면 닫는다.
```

알림음이 울리고 결제창이 뜬다. **연습이므로 결제하지 않고 창을 닫는다.**
설정이 `"payment": "manual"` 이면 마지막 줄이 `[사용자 차례] 좌석을 잡았다. … 결제수단을 고르고 결제하기를 누른다` 이고
결제창은 뜨지 않는다. 연습이므로 아무것도 누르지 않는다.

`'blocked': 1, 'unblocked': 0` 은 준비 중에 사이트가 보내려던 주문 요청을 프로그램이 막았다는 뜻이다. 정상이다.

## 3. 실패하면

콘솔의 마지막 몇 줄이 이유다. [문제 해결](troubleshooting.md)에서 그 문구를 찾는다. 자주 나오는 것:

| 마지막에 나온 말 | 뜻 |
|---|---|
| `로그인 필요` | [로그인](login.md)을 다시 한다 |
| `캡처 날짜를 고를 수 없다` | 달력에 일반석이 남은 열린 날짜가 없다. 편·요일이 맞는지 본다 |
| `준비 통과가 … 끝나지 않았다` | 스스로 Chrome 을 다시 띄워 두 번 더 해 본다. 세 번 다 안 되면 [문제 해결 §2](troubleshooting.md) |
| `판정=sold-out` 또는 `no-target` | 연습 날짜에 그 편의 일반석이 없다. `--date` 로 다른 날을 준다 |
| `판정=business-error` | 주문이 거절됐다. 그 사이 좌석이 팔렸다. 다른 날짜로 다시 |

## 4. 연습으로 확인되는 것, 안 되는 것

| 확인된다 | 확인되지 않는다 |
|---|---|
| 이 PC 에서 로그인·준비·발사·주문·결제창까지 끊기지 않는다 | 09:00 의 경쟁에서 이기는지 |
| 계정·마일리지·편명 설정이 맞다 | 프레스티지 좌석이 그날 열리는지 |
| 결제 수단 화면이 내 카드로 이어진다 | 예약(작업 스케줄러)이 그 시각에 뜨는지 → [실전 §2](real-day.md) |

연습이 된다고 실전이 되는 것은 아니다. 2026-09 에 엿새 실전 가운데 사흘은 좌석이 한 석뿐이었고 우리보다 먼저 팔렸다
([왜 이렇게 만들었나](why.md)).

## 5. 예약이 그 시각에 뜨는지 보려면

실전과 똑같이 작업 스케줄러로 띄워 보고 싶으면, `config/run.json` 의 `trip.date` 를 이미 열린 날짜로, 등급을 일반석으로,
`times` 를 오늘의 가까운 시각으로 잠깐 바꾼 뒤 `astra schedule --date <오늘>` 을 쓴다. 계정마다 미결제 예약이 하나씩 생긴다.
끝나면 설정을 되돌린다. 꼭 필요하지는 않다 — 예약이 등록됐는지는 `astra schedule --list` 로 보인다.
