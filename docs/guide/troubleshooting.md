# 문제 해결

먼저 `.\astra.cmd status` 와 콘솔 창(또는 `dev-shots/api-day/*-console.log`)의 **마지막 열 줄**을 본다.
정상 실행에서 나오는 줄의 순서는 [증거 견본](../samples/README.md)에 있다 — 어디서 끊겼는지가 원인의 위치다.

## 1. 시작도 안 했다

| 증상 | 원인 | 처리 |
|---|---|---|
| 08:20 에 콘솔 창이 안 떴다. `status` 가 "아직 시작하지 않았다" | PC 가 절전·종료 상태였거나 Windows 에서 로그아웃돼 있었다 | [PC 설정](install.md#4-pc-설정--실전-날-아침에-pc-가-깨어-있어야-한다). 예약은 로그인한 사용자의 화면에서만 뜬다 |
| | 예약이 안 돼 있었다 | `.\astra.cmd schedule --list` 로 확인 |
| | 같은 이름의 지난 콘솔 창이 "계속하려면 아무 키나…"로 남아 있었다 | 지난 창을 닫는다. 남아 있으면 새 실행이 무시된다(2026-09-20 에 겪었다) |
| `schedule` 이 "준비 시작 시각 … 이 이미 지났다" | 그날 08:20 이 지났다 | 발사 12분 전까지는 `.\astra.cmd run` 으로 바로 시작할 수 있다 |
| `astra.cmd` 가 "Python 3 was not found" | Python 이 없거나 PATH 에 없다 | [설치 §1](install.md) |

## 2. 준비에서 멈췄다 — 주문은 나가지 않았다

이 단계의 실패는 좌석과 무관하다. 프로그램이 스스로 Chrome 을 다시 띄워 **세 번까지** 다시 해 본다(08:52 까지).

| 콘솔의 말 | 원인 | 처리 |
|---|---|---|
| `로그인 필요` | 네이버 연동 창이 비밀번호를 묻는다(로그인 유지가 꺼져 있었거나 한 달이 지났다) | `.\astra.cmd login --account <이름>`. [로그인 §2](login.md) |
| `로그인 필요: 스카이패스 로그인 실패` | `.env` 의 아이디·비밀번호·탭 | [로그인 §1](login.md) |
| `로그인 확인 필요: 현재 … 세션이 … 인데 정책은 …` | 그 창에 다른 방식으로 로그인된 흔적이 있다(설정의 `login` 을 바꾼 뒤 등) | 그 창에서 대한항공을 로그아웃하고 `astra login` |
| `달력 복귀 실패` | 노선·날짜를 넣었는데 마일리지 달력이 안 열렸다 | 대한항공 누리집에서 그 노선의 마일리지 예매가 열리는지 직접 본다. 공항 코드가 맞는지 |
| `캡처 날짜를 고를 수 없다` | 목표보다 앞선 날 중 일반석이 남은 열린 날짜가 달력에 없다 | 편·요일 확인. 정 없으면 `trip.captureDate` 에 일반석이 남은 열린 날짜를 직접 적는다 |
| `검색 N회차 이동 없음, 재시도 · 누른 곳 … · {…}` | 달력의 [검색]이 눌리지 않았다 | 세 번 다 안 되면 종료 코드 4 로 끝나고 Chrome 을 다시 띄워 재준비한다. 뒤에 붙은 `{inner, buttons}` 가 그때의 화면 상태다 — 물어볼 때 같이 보낸다. [배경](#검색-이동-없음) |
| `통화 KRW 확인: False` | 통화가 원화로 안 바뀌었다 | 다시 준비하면 대개 된다 |
| `다음 → …select-award-flight/departure` 뒤에 `준비 통과가 … 끝나지 않았다`(세 번 다) | [다음]을 눌렀는데 넘어가지 않았다. 그 창에 **"마일리지 부족 안내"** 가 떠 있을 것이다 — 잔액이 캡처 날짜의 일반석 값보다 적다 | `astra check --online` 으로 실제 잔액을 본다. 목표 좌석 값은 되는데 캡처 날짜가 성수기라 막힌 것이면 `trip.captureDate` 에 평수기 날짜를 적는다 |
| `운임 선택: False` / `캡처 날짜 … 에 KE… 일반석 운임 칸이 없다` | 캡처 날짜에 그 편의 일반석이 없다 | `"captureDate": "auto"` 면 다음 시도에서 다시 고른다. 직접 적었으면 다른 날로 |
| `이번 준비에서 캡처하지 못한 경로: […]` | 같은 Chrome 에서 두 번째 준비라 사이트가 주문 요청을 다시 보내지 않았다 | 스스로 Chrome 을 다시 띄운다(2026-09-20 에 확인한 사이트 동작) |
| `**준비 중 주문 요청을 막지 못했다…**` | 준비 중 사이트의 주문 요청이 새어 나갔다 | **다시 실행하지 않는다.** 캡처 날짜에 미결제 예약이 생겼을 수 있다. 예약 조회로 확인(결제하지 않으면 풀린다) |
| `재준비 마감이 지났다 - 발사하지 않는다` | 08:52 까지 준비가 안 끝났다 | 그날은 끝. 원인은 그 앞줄들 |
| `[arm]`/`[health]` `점검 … 실패` | 로그인 토큰이 발사 전에 끊길 예정이거나 화면 상태가 달라졌다 | 스스로 다시 준비한다(종료 코드 3) |

## 3. 발사했는데 못 잡았다

| 콘솔의 말 | 뜻 | 처리 |
|---|---|---|
| `조회#N … 판정=not-open` 이 이어지다 끝 | 정각+8초까지 그 날짜가 안 열렸다 | 개방일이 맞는지(`astra plan`). 대한항공이 그날 그 편을 안 열었을 수 있다 |
| `판정=sold-out` / `no-target` | 열렸지만 그 편·그 등급 좌석이 없다 | 프레스티지는 아예 안 풀리는 날이 있다. 대체 등급을 둔다 |
| `주문 … 판정=business-error`, `ERT.15012` | 주문이 거절됐다. 운임을 확인한 뒤 주문 사이에 좌석이 팔렸다 | 고장이 아니다. 2026-09 에 엿새 중 나흘 겪었다 |
| `대체 게이트: seat-taken - 주문하지 않는다` | 1순위가 잡아서 대체가 주문하지 않았다 | 정상 |
| `대체 게이트: timeout - 주문하지 않는다` | 1순위의 결과가 제때 안 와서 대체가 주문하지 않았다 | 1순위 실행이 발사 전에 죽었는지 본다 |
| `대체 게이트: ambiguous:… - 주문하지 않는다` | 1순위의 결과가 애매하다(좌석이 잡혔을 수도 있다) | 1순위 쪽 결과를 예약 조회로 확인한다 |
| `필수 검증·주문 준비 판정=insufficient-mileage` | 설정의 `mileage` 가 그 좌석의 필요 마일리지보다 적다 | 실제 잔액이 충분하면 [설정 §1.2](config.md#12-accounts--누가-무엇을-잡나)의 숫자를 고친다 |
| `시작 거부: fire-time-passed` | 실행이 발사 시각 뒤에 시작됐다 | 시각 설정 확인 |
| `**새 주문을 보내지 않는다.**` | 12시간 안에 이 자리에서 주문을 보낸 기록이 있다 | [실전 §7](real-day.md#7-못-잡았을-때--다시-시도) |

## 4. 좌석은 잡았는데 결제 화면이 이상하다

| 증상 | 처리 |
|---|---|
| `status` 가 "좌석을 잡았다. 결제창은 열지 못했다" | 예약은 있다. 대한항공 누리집·앱 → 예약 조회 → 결제. **보유 시간(10~32분을 봤다) 안에** |
| 결제창이 내 카드가 아니다 | 지금은 창을 닫고 대한항공 화면에서 결제수단을 바꿔 결제한다. 다음부터는 설정의 `"payment"` 를 `"manual"` 로([설정 §1.7](config.md#17-payment--좌석을-잡은-뒤-어디까지-해-줄지)) |
| `manual` 인데 결제 화면이 안 보인다 | 다른 창 뒤에 있다. 작업 표시줄의 Chrome 아이콘에서 제목이 `[ASTRA · <자리>]` 로 시작하는 창을 연다 |
| 콘솔이 `인계 … storage-changed` 로 끝났다 | 주문은 기록됐고 화면 넘기기만 실패했다(2026-09-24 에 두 번, 원인 미확인). 예약 조회에서 결제 |
| 예약 조회에 안 보인다 | 결제 전 좌석 확보 단계는 예약 목록에 안 보일 수 있다(2026-09-14 관찰). 결제창·콘솔 기록을 믿는다 |

## 5. 그 밖

| 증상 | 처리 |
|---|---|
| 창이 다섯 개나 뜬다 | 계정 2 × (1순위·대체) + 계측. 필요 없는 것은 설정에서 `fallback: null`, `observer: null` |
| 어느 Chrome 이 프로그램 것인가 | 제목이 `[ASTRA · 9232] 예매` 처럼 시작하는 창이다. 실전 중에는 건드리지 않는다 |
| PC 시계가 몇 초 틀리다 | 괜찮다. 콘솔의 `시계 보정 … 오프셋 …ms` 가 그 차이다. 프로그램은 보정한 시각으로 쏜다 |
| "계측"이 실패했다 | 예매와 무관하다. `dev-shots/api-day/observer-*.log` |
| 전용 Chrome 을 끄고 싶다 | 창을 닫는다. 명령으로는 `.\.venv\Scripts\python.exe dev\close_astra_browser.py --port 9232` |
| 처음부터 깨끗이 다시 | `config/run.json` 과 `.env` 를 고친다. 로그인까지 지우려면 `.debug-profile*`·`.api-profile*` 폴더를 지운다 |

### 검색 이동 없음

달력에서 [검색]을 눌렀는데 항공편 목록으로 넘어가지 않는 증상이다. 2026-09-25 에 네 실행 중 둘이 이것으로 멈췄다.
2026-10-04 실사이트 조사에서 좌표 클릭이 조용히 헛도는 경우 둘을 재현했다.

- 창 안쪽 너비가 약 1,050px 이하면 [검색]이 달력 아래 본문에 놓여 창 밖으로 나간다. 창 밖 좌표는 눌리지 않는다.
- 글자가 "검색"인 버튼이 화면에 둘 있다(달력의 것, 머리말의 사이트 검색 아이콘).

지금은 머리말 밖의 버튼을 고르고, 창 밖이면 끌어온 뒤 누르고, 준비를 시작할 때 창을 1600×1000 으로 맞춘다.
다만 9/25 의 두 실패가 정확히 이 두 경우였는지는 확정하지 못했다. 그래서 다시 나면 화면 상태를 한 줄 남기게 해 두었다.
경위는 [2026-10-05 결과](../results/2026-10-05.md).
