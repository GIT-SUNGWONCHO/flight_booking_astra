## 7. 템퍼몽키 vs Playwright, 막히는 곳, 계정 잠김 — **판단**

> 현재 템퍼몽키를 활용하는 방식이 이대로 괜찮을지, playwrite등 더 빠른방식을 사용해야할지

- **속도는 동일하다.** 둘 다 같은 Chrome 에서 같은 DOM 클릭을 한다.
  CDP 의 장점은 속도가 아니라 *무인 실행·다중 탭·계측*이다.
- 지문 확인: `navigator.webdriver=false`, plugins 5, cdc/selenium 흔적 없음,
  Akamai 쿠키(`_abck`,`bm_*`)는 모든 방문자에게 정상 발급. **깨끗하다.**
- **API 직접 호출은 막혔다.** 조회 요청을 그대로 재현하니 서버가 `IBE-AP.1001` 로 거부.
  뚫으려면 봇 방어 우회가 되는데, 마일리지가 걸린 계정으로 할 일이 아니다.
- **결론: 둘 다 유지.** 테스트·무인은 CDP, 수동 백업은 템퍼몽키. 같은 빌드를 쓴다.

## 8. 테스트 계정 필요성 / 잠김 우려 — **판단**

> 혹시모를 잠김우려 떄문에 별도 테스트 계정을 만들어서 해봐야되는거 아닌지 검토,
> 근데 테스트 계정은 마일리지가 없을거기때문에 마일리지 예매 페이지 접근이 안될수도있음

- **권하지 않는다.** 마일리지 예매 화면은 마일리지가 있어야 들어가므로 0마일 계정으로는
  정작 중요한 구간을 못 밟는다. 계정을 새로 만드는 것 자체도 약관 리스크다.
- 실질적 위험 순위: 잠김보다 **미결제 주문 반복 생성**이 가장 눈에 띄는 패턴이다.
  → `--dry` 로 7단계 앞에서 멈추는 모드를 만들어 반복 테스트는 그걸로 한다.
- 요청 빈도는 낮다(재조회 하한 800ms). 남는 신호는 마우스 이동 없는 클릭뿐이고,
  이건 템퍼몽키여도 동일하다.

## 9. 모바일 검토 — **미착수**

> 모바일 앱/웹과 PC웹이 UI가 조금씩 다른 걸로 보임, 모바일부분도 검토해보고,
> 혹시 모바일이 더 빠르진 않은지, PC웹으로도 충분한지 검토 필요

- 아직 재보지 않았다. 같은 Chrome 의 기기 에뮬레이션으로 속도 측정은 가능하다.
- 모바일 레이아웃은 셀렉터가 달라 **별도 녹화가 필요**하다(녹화는 내가 할 수 있다).
- 먼저 속도를 재고, 유의미할 때만 녹화한다.
