# 대한항공 마일리지(보너스) 항공권 예매 보조

프레스티지처럼 1~2석뿐인 좌석을, 오픈 시각에 놓치지 않기 위한 개인용 도구입니다.

## 이 도구가 실제로 해결하는 것

병목은 **조회가 아니라 좌석 선택 이후의 안내사항 확인 구간**입니다.
사람이 모달 하나를 읽고 누르는 데 400~800ms, 4~6개면 3~5초. 그 사이에 남이 먼저
끝내면 세션이 끊깁니다.

손으로 한 번 밟은 순서를 **녹화해두고 그대로 재생**하면 이 구간이 사라집니다.
koreanair.com 실측: 날짜 클릭부터 결제 직전까지 **15단계 18.4초**
(그중 10초는 지금은 제거한 추측 클릭 엔진과의 충돌이었습니다).

새로고침 연타는 도움이 안 됩니다. 병목은 조회가 아니라 그 뒤 구간입니다.

## 두 가지 사용법

| | A. 유저스크립트 (권장) | B. Playwright 풀오토 |
|---|---|---|
| 실행 환경 | 평소 쓰는 Chrome 그대로 | 별도 프로필의 Chrome/Chromium |
| 로그인 | 이미 되어 있음 | 한 번 수동 로그인 후 프로필에 저장 |
| 자동화 탐지 위험 | 낮음 (진짜 브라우저·진짜 세션) | 상대적으로 높음 |
| 준비 난이도 | 낮음 | 중간 (probe로 URL/셀렉터 확보 필요) |

**A를 주력으로 쓰고, B는 예열·재조회까지 완전 무인으로 돌리고 싶을 때** 쓰세요.

## A. 유저스크립트

1. Chrome에 [Tampermonkey](https://www.tampermonkey.net/) 설치
2. `node build.mjs` 실행 → [userscript/ke-award-macro.user.js](userscript/ke-award-macro.user.js) 생성
3. Tampermonkey 대시보드 → 새 스크립트 → 파일 내용 붙여넣기 → 저장
4. koreanair.com 접속하면 우상단에 패널이 뜹니다

패널 사용법:

| 컨트롤 | 하는 일 |
|---|---|
| **시각 동기** | 서버 `Date` 헤더의 초 전환 지점을 잡아 로컬 시계 오차를 ~50ms로 보정 |
| **좌석 등급** | `일반석`(연습) / `프레스티지`(실전) 등. 좌석 단계가 이 등급으로 카드를 찾음 |
| **목표 날짜** | 넣으면 자동 감지한 최신 오픈일이 이것과 다를 때 **누르지 않고 멈춤** |
| **결제하기까지 자동** | 기본 **켜짐**. 결제창(네이버페이 등)까지 띄웁니다 (아래 주의) |
| **● 녹화 / ▶ 재생 / 삭제** | 예매 단계 녹화·재생 (아래 참고) |
| **단계 편집** | 삭제 / 순서 이동 / 빠뜨린 단계 끼워넣기 |
| **내보내기** | `ke_award/steps.json` 에 붙여넣을 JSON 을 뽑음 |
| **연습 (10초 뒤 발사)** | 오픈시각을 10초 뒤로 잡고 전체 흐름을 그대로 리허설 |
| **대기 시작** | 설정한 오픈시각에 정시 발사 |

입력값:

- **오픈시각** — `2027-03-15 10:00:00` 형식(KST)
- **선발사(ms)** — 네트워크 지연 보정. 150 정도에서 시작

### 결제창이 안 뜰 수 있습니다 — 눈으로 확인하세요

실측에서 결제하기 단계가 로그상 "실행됨" 으로 찍혔는데도 결제창이 뜨지 않았습니다.
브라우저는 스크립트가 만든 클릭(`isTrusted=false`)에 사용자 조작 권한을 주지 않아
새 창을 막는 경우가 있고, 그러면 **눌렀다는 기록만 남고 실제로는 아무 일도
일어나지 않습니다.**

자동 클릭은 기본으로 켜져 있습니다. 다만 로그에 "결제하기" 가 찍혀도 **결제창이
실제로 떴는지 반드시 눈으로 확인**하세요. 안 떴으면 그 버튼만 직접 누르면 됩니다
(주소창 오른쪽에 팝업 차단 아이콘이 떴는지도 같이 보세요).

### 클릭은 녹화 재생 하나만 합니다

예전에는 `확인`/`동의` 같은 라벨이 보이면 무조건 누르는 **추측 클릭 엔진**이 같이
돌았습니다. 녹화 재생이 생기기 전의 유일한 수단이었는데, 실측 로그에서 해가 되는 게
드러나 제거했습니다:

- 재생이 6단계를 마치자 추측 엔진이 먼저 `확인`/`동의`를 눌러 위험물 팝업을 띄웠고,
  재생이 노리던 7단계 버튼이 그 팝업에 가려 **10초를 그냥 기다렸습니다**
- 재생이 끝난 뒤에도 계속 눌러서, **결제 버튼 직후에 뜬 팝업을 사람이 읽기 전에
  치워버렸습니다**

녹화가 순서를 정확히 알고 있는데 옆에서 추측으로 누르면 방해만 됩니다. 녹화에 없는
팝업이 뜨면 재생은 20초 기다린 뒤 `⚠멈춤⚠` 소리와 함께 멈춥니다 — 예매 화면에서
예상 못한 창이 떴으면 사람이 읽는 게 맞습니다.

(Playwright 러너는 녹화가 없는 경로라 [ke_award/autoconfirm.js](ke_award/autoconfirm.js)
를 계속 씁니다.)

### 시작 화면 고르기 (달력 / 조회 화면)

패널의 **시작 화면** 이 두 가지입니다. **발사할 때 그 화면에 서 있어야 합니다.**

| 모드 | 서 있어야 할 곳 | 09:00 에 하는 일 |
|---|---|---|
| **달력** (기본) | `/booking/calendar-fare-bonus` | 새로고침 → 새로 열린 날짜 클릭 → 검색 → 조회 |
| **조회 화면** (미완성) | `/booking/select-award-flight/departure` | 그 자리에서 새로고침 → 바로 좌석 선택 |

조회 화면 모드는 09:00 에 이렇게 돕니다:

```
그 자리에서 새로고침
  → 날짜칸을 눌러 달력을 열고
  → 목표 날짜가 -available 이 되면 클릭
  → [항공편 검색] 클릭
  → 서버 응답이 그 날짜라고 확인되면 → 좌석 선택
```

미리 맞춰둘 필요가 없습니다. 새로 열리는 날짜는 09:00 에야 예약 가능 창에 들어오므로
애초에 미리 고를 수도 없습니다.

**엉뚱한 날 예매를 막는 근거는 서버 응답입니다.** 날짜를 누른 *뒤에* 온 응답이 목표
날짜를 말할 때만 좌석 단계로 넘어갑니다. 낡은 응답은 근거로 치지 않습니다 - 실측에서
날짜만 바뀌고 목록은 그대로인 경우가 있었고, 그때 낡은 응답을 믿었으면 어제 날짜로
예매될 뻔했습니다.

못 하면 좌석을 누르지 않고 무엇이 안 됐는지 말합니다:

```
조회 화면을 08-22 로 바꾸지 못했습니다 (달력을 열지 못함)
                                    (그 날짜 칸을 누르지 못함)
                                    (날짜는 바꿨는데 조회 버튼을 못 찾음)
                                    (날짜와 조회를 눌렀는데 목록이 안 바뀜)
```

**아직 09:00 실전에서 돌려본 적은 없습니다.** 중요한 날이면 검증된 [달력] 모드를 쓰세요.

패널이 지금 제대로 서 있는지 초록/빨강으로 알려줍니다:

```
✔ 준비됨 - 이 조회 화면(08-22)에서 새로고침, 3단계부터
✖ 이 화면은 08-21 인데 목표는 08-22 입니다 - 조회 화면을 08-22 로 맞춰두고 대기하세요
✖ 지금 달력 화면이 아닙니다 - 달력을 띄워두고 대기하세요
```

**좌석이 정각에 조금 늦게 열려도 기다립니다.** 새로고침했는데 그 등급이 아직 없으면
1.2초 간격으로 다시 불러옵니다(달력에서 목표 날짜를 기다릴 때와 같습니다). 3분이
지나도 안 나오면 멈추고 소리로 부릅니다.

엉뚱한 날 예매를 막기 위해, **지금 화면이 몇 일자인지 확인되지 않으면 건너뛰지
않습니다.** 조용히 넘어가지 않고 이유를 말한 뒤 달력 경로로 갑니다.

주소로 바로 뛰어드는 방법은 안 됩니다. 조회 페이지 주소에는 날짜가 없고
(`/departure` 뿐), 서버가 `pageTicket` 으로 흐름 순서를 강제합니다.

### 좌석이 언제 매진이 되는지 (조사 중)

잔여석은 HTML 에 박혀 있지 않고 API 응답으로 받아서 그립니다. 그래서 화면을 뒤져도
안 나옵니다. 패널의 `조회 응답` 버튼이 그 응답 기록을 보여줍니다 — 09:00 에 사람이
개발자도구를 붙잡고 있을 수 없으니 자동으로 남깁니다(엿보기만 하고 값은 바꾸지 않으며,
좌석/운임 조회로 보이는 것만 남깁니다).

확인하려는 것: 좌석을 고르고 `다음` 을 누르는 순간 서버가 좌석을 잠그는지 여부.
잠근다면 결승선은 `결제하기` 가 아니라 `다음`(실측 7.8초 지점)이고, 그 뒤 14.8초는
경쟁이 아니다 — 무엇을 줄여야 하는지가 통째로 바뀝니다. BACKLOG 5번.

### 창을 넓게, 최소화하지 마세요

**창 너비가 가장 흔한 실패 원인입니다.** 대한항공 화면은 반응형이라 창이 좁아지면
모바일 레이아웃으로 바뀌는데, 그러면 셀렉터도 버튼 라벨도 통째로 달라집니다.
위험품 안내 모달은 넓은 화면에는 `[아래로 스크롤]` 버튼이 있지만 좁은 화면에는
아예 없습니다(그냥 스크롤합니다).

실측(2026-08-28): 창을 줄여놓고 돌렸더니 12단계에서 그 버튼을 못 찾고 멈췄고,
최대화하면 잘 됐습니다.

녹화할 때의 창 너비를 기억해두고, 그보다 많이 좁으면 패널이 미리 빨갛게 알립니다:

```
⚠ 창이 좁습니다 (700px) - 모바일 화면으로 바뀌면 단계를 못 찾습니다. 창을 1400px 이상으로 넓히세요
```

멈췄을 때의 메시지에도 같은 말이 붙습니다 - 원인을 못 찾고 헤매지 않도록.

### 최소화해도 돌게 하려면 (크롬 플래그)

크롬은 안 보이는 창의 **페이지 전체**를 늦춥니다. 우리 매크로만이 아니라 대한항공
자기 자바스크립트도 멈춥니다. 그래서 페이지 안에서는 못 이깁니다 - 모달이 안 그려지면
누를 것이 없습니다.

크롬을 그렇게 안 만들 수는 있습니다. 바로가기를 하나 만들고 대상에 붙이세요:

```
"C:\Program Files\Google\Chrome\Application\chrome.exe" --disable-background-timer-throttling --disable-backgrounding-occluded-windows --disable-renderer-backgrounding
```

**이 테스트들이 계속 통과한 이유가 바로 이 플래그입니다** - Playwright 가 크롬을
이렇게 띄웁니다. 그래서 테스트에서는 이 문제가 아예 나타나지 않습니다. 실제 크롬과
다른 지점이라 사람 눈으로 확인해야 합니다.

말로만 하지 않고 **패널이 직접 재서 알려줍니다.** 창을 잠깐 가렸다가 돌아오면:

```
✔ 가려져도 안 늦는 크롬입니다 (최대 62ms)
⚠ 이 크롬은 가려진 창을 늦춥니다 (재보니 1004ms 까지 벌어짐) - 창을 보이게 두거나 스로틀링 끈 크롬을 쓰세요
```

플래그를 안 쓰신다면 **재생 구간에는 창을 보이게 두는 수밖에 없습니다.** 무장 중
(대기 시작 ~ 09:00)에는 안 들리는 소리로 스로틀링을 피하므로 최소화해도 정시에 쏩니다.
다만 발사하며 새로고침하면 그 소리가 끊기고, 새 문서에서는 사람이 클릭하지 않으면
다시 낼 수 없습니다(크롬 자동재생 정책).

가려져 있던 시간은 인내심에서 빼고 세므로, 잠깐 가렸다고 바로 포기하지는 않습니다 -
멈춤 메시지에 "창이 가려져 있던 N초는 빼고 셌습니다" 라고 적힙니다.

### 무장해두고 자리를 비울 때
### 날짜와 좌석은 "그때 화면"에서 다시 찾습니다

녹화한 날짜·편명·마일리지를 그대로 쓰면 다음 날 바로 깨집니다. 그래서 두 단계는
고정값이 아니라 규칙으로 찾습니다:

- **날짜** — 달력에서 *예약 가능한 것 중 가장 나중 날짜*. 마일리지 좌석은 매일
  09:00 KST 에 하루치씩 새로 열리므로, 이게 곧 "오늘 새로 열린 날"입니다.
  엉뚱한 날 예매를 막으려면 **목표 날짜**(예: `08월 17일`)를 넣어두세요. 다르면 멈춥니다
- **좌석** — 라벨의 *등급 이름 + "마일"* 로 찾습니다. 편명(KE901)이나 필요 마일리지
  (성수기/평수기에 따라 다름)가 바뀌어도 그대로 동작합니다

재생 중 어떤 단계의 요소를 못 찾으면, 사이트가 화면을 건너뛰었거나 그 버튼이 이미
처리된 경우일 수 있습니다. 이때는 뒤쪽 단계(최대 3개)를 넘겨보고 이미 지나간
것으로 보이면 **건너뛰고 따라잡습니다**. 단, 결제 단계로는 절대 건너뛰지 않습니다.

**연습 버튼이 실전과 같은 경로를 탑니다**: 카운트다운 → 정시 발사 → **새로고침** →
녹화 단계 재생 → 결제 직전 정지 + 소리 알림. 결제 버튼만 안 누릅니다.

> 정시 동작은 **새로고침이 끝난 뒤에** 재생을 시작합니다. 낡은 화면에서 1단계(그날 새로
> 열린 날짜)를 눌러봤자 이어지는 새로고침이 그 선택을 날려버리기 때문입니다.

> 예전엔 "조회 버튼 지정 + 좌석 자동 클릭" 경로도 있었지만, 녹화 재생이 그 일을 전부
> 대신하므로 관련 컨트롤(조회 지정 / 좌석 지정 / 발사 테스트 / 버튼 확인 / 동작 전환 /
> 재조회)은 제거했습니다.

### 단계 녹화 / 재생 (핵심)

실제 예매는 정해진 순서라서, 라벨 추측보다 **손으로 한 번 한 걸 그대로 재생**하는 쪽이
정확합니다. 특히 (a) 매일 바뀌는 날짜 버튼 (b) 이미 동의된 버튼을 다시 눌러 동의가
풀리는 사고 는 추측으로 막을 수 없습니다.

| 버튼 | 하는 일 |
|---|---|
| **● 녹화** | 이후의 모든 클릭을 순서대로 기록 (패널 자체 클릭은 제외) |
| **▶ 재생** | 기록한 순서대로 재생. 각 단계는 요소가 나타날 때까지 최대 20초 대기 |
| **삭제** | 기록 초기화 |
| **단계 편집** | 삭제 / 순서 이동 / 빠뜨린 단계 끼워넣기 |
| **내보내기** | `ke_award/steps.json` 에 붙여넣을 JSON 을 뽑음 |

- **페이지가 바뀌어도 이어서 재생합니다.** 진행 위치를 localStorage에 두기 때문에
  조회 → 결과 → 정보입력 → 결제처럼 이동이 끼어도 끊기지 않습니다
- **`결제하기` 앞에서 반드시 멈춥니다.** 마일리지와 현금이 실제로 빠지는 지점이라
  자동으로 넘기지 않습니다 (`KE_REC.state.allowPay = true` 로 풀 수는 있음)
- 요소를 20초 안에 못 찾으면 멈추고 몇 번째 단계에서 막혔는지 표시합니다

#### 녹화를 고치기

한 번에 깔끔하게 녹화되지 않습니다. **단계 편집**에서:

- **✕** 괜히 눌린 단계 삭제 (스크롤 중복 등)
- **↑↓** 순서 바로잡기
- **＋ 여기에 추가** 빠뜨린 단계 끼워넣기 → 누르면 커서가 십자로 바뀌고,
  화면에서 그 버튼을 클릭하면 그 자리에 삽입됩니다 (실제로 눌리지는 않음)
- **고정** 라벨이 매일 바뀌는 버튼(날짜)에 켜면 셀렉터만 쓰고 텍스트는 무시합니다

#### PC 를 옮길 때

녹화는 브라우저 localStorage 에 있어서 그대로는 안 따라갑니다. **내보내기** 로 뽑아
[ke_award/steps.json](ke_award/steps.json) 에 덮어쓰고 커밋하면, 빌드할 때 스크립트
안으로 들어가서 어느 PC 에서든 같은 단계를 들고 갑니다.

```powershell
# steps.json 갱신 후
node build.mjs      # "내장 단계 N개" 가 찍히면 성공
```

브라우저에 직접 녹화한 게 있으면 그쪽이 우선합니다. 내장본을 강제로 쓰려면
콘솔에서 `KE_REC.loadBaked()`.

녹화 순서 예시 (님 플로우 그대로):

```
1 16(월)          <- 9시에 새로 열린 날짜
2 항공편 검색
3 프레스티지 P     <- 좌석
4 다음
5 확인            <- 승객정보
6 아래로 스크롤    <- 위험품 안내 팝업
7 아래로 스크롤
8 확인
9 동의            <- 안 켜진 것 하나만
10 네이버페이
-- 결제하기는 직접 --
```

콘솔 도구:

```js
KE_REC.list()              // 단계 목록을 표로
KE_REC.pause()             // 재생 즉시 정지
KE_REC.loadBaked()         // steps.json 내장본으로 되돌리기
KE_REC.state.allowPay      // 결제하기 자동 여부 (기본 false)
KE_UTIL.label(KE_UTIL.findLatestOpenDate())   // 날짜 자동감지가 뭘 고르는지
```

```powershell
# Windows
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
./.venv/Scripts/python.exe -m playwright install chromium
copy config.example.yaml config.yaml
```

```bash
# macOS / Linux
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
cp config.example.yaml config.yaml
```

```powershell
./.venv/Scripts/python.exe -m ke_award clock    # 시계 오차 확인
./.venv/Scripts/python.exe -m ke_award login    # 한 번 수동 로그인 → 프로필 저장
./.venv/Scripts/python.exe -m ke_award probe    # 리허설: URL/버튼 라벨 수집
./.venv/Scripts/python.exe -m ke_award run      # 본 실행
```

`probe`는 자동 클릭을 끈 채로 손으로 한 번 흐름을 밟게 하고, 결과를
`probe_result.txt`에 남깁니다. 그 값으로 [config.yaml](config.example.yaml)의
`search_url` / `seat_selector` / `success_text`를 채우세요.

이 PC의 Chrome은 정책 때문에 자동화 실행이 막혀 있어서, 테스트는 번들 Chromium으로
돌렸습니다. `run`에서도 Chrome 실행이 실패하면 자동으로 번들 Chromium으로 넘어가고,
계속 실패하면 `browser_channel: ""`로 두면 됩니다.

## 실전 운영 순서

**D-30 (한가할 때 리허설)** — 이게 성패의 90%입니다.
다른 날짜/노선으로 실제 예매 흐름을 끝까지(결제 직전까지) 밟아보면서:

- 녹화가 실제 화면과 맞는지 (단계 편집에서 확인)
- **연습** 버튼으로 새로고침까지 포함한 전 구간이 끊기지 않는지

**D-1**

- 좌석 오픈 정확한 시각을 대한항공 공지로 재확인 (아래 주의 참고)
- 마일리지 잔액, 탑승객 정보(여권 영문명·생년월일)가 미리 등록돼 있는지
- `clock` 또는 패널의 **시각 동기** 실행

**당일 (T-10분)** — 좌석 오픈은 매일 09:00 KST, 36x일 뒤 날짜가 새로 열립니다
(정확한 일수는 대한항공 공지로 확인).

- 로그인 → 구간 지정 → **캘린더 화면을 띄워둠**
- 패널: **오픈시각 `09:00:00` 입력** → **▶ 대기 시작**
- 09:00 정각에 새로고침이 걸리고, 새 화면에서 녹화 단계가 자동으로 흘러갑니다
  (1단계는 그날 새로 열린 날짜를 자동으로 찾아 누릅니다)
- 결제 직전에서 멈추면 **네이버페이 → 결제하기**만 직접 누르세요
- 탭을 포그라운드로 유지 (백그라운드면 `requestAnimationFrame`이 멈춤 —
  `MutationObserver`는 계속 도니 치명적이진 않지만 반응이 느려집니다)
- 화면에서 눈 떼지 말 것. 마지막 발권 버튼은 직접 누르는 게 기본값입니다

## 주의

**약관과 계정.** 자동화 접근은 대한항공 이용약관에 저촉될 수 있고, 과도한 요청은
봇으로 판정되어 계정이 잠길 수 있습니다. 본인 계정으로 본인 여정을 예매하는 용도로만
쓰고, 재조회 간격을 낮추지 마세요. 낮춰도 병목은 조회가 아니라서 이득이 없습니다.

**마일리지는 실제로 차감됩니다.** `auto_final`은 기본 `false`입니다. `true`로 바꾸면
최종 발권 버튼까지 자동으로 눌러 마일리지가 빠져나갑니다. 리허설을 충분히 하기 전에는
켜지 마세요.

**직접 확인해야 하는 것.** 좌석 오픈 시점(출발일 기준 며칠 전, 그날 몇 시)과
프레스티지 필요 마일리지, 유류할증료는 노선·시즌에 따라 다르고 정책도 바뀝니다.
이 도구는 그 값을 알지 못하므로 대한항공 공지에서 직접 확인해 `open_at`에 넣으세요.

**2인 예약.** 프레스티지 잔여가 1석뿐이면 2인 조회로는 아예 안 잡힙니다.
1인씩 나눠 예약하는 방식이 가능한지는 대한항공 규정을 확인하세요.

  재현하는지 / 동의를 풀지 않는지 / 결제 앞에서 멈추는지 검증

테스트가 실제로 잡아낸 버그들:

1. 버튼 라벨의 `»` `›` `→` 글리프 때문에 `확인 »`을 놓침 → 기호 블랙리스트를
   한글·영문·숫자 화이트리스트로 교체
2. `document-start` 주입 시점엔 `document.documentElement`가 아직 `null`이라
   `MutationObserver.observe()`가 throw → 스크립트 전체가 죽어 아무것도 안 눌림.
   `document`를 관찰하도록 변경 ([ke_award/autoconfirm.js](ke_award/autoconfirm.js))
3. `@grant none` + 대한항공 CSP → Tampermonkey 의 페이지 컨텍스트 주입이 차단되어
   패널이 아예 안 뜸. `@grant unsafeWindow` 로 샌드박스 실행하도록 변경
   ([build.mjs](build.mjs)). 실제 사이트에서 확인된 문제
4. 연습 발사가 초 단위 절삭 때문에 최대 1초 일찍 발사 → 초 경계로 올림
5. 이미 동의된 버튼을 자동클릭이 다시 눌러 **동의를 풀어버리는** 경로 →
   `aria-pressed`/상태 클래스로 켜짐을 감지해 토글성 라벨은 건너뛰도록 변경
   ([ke_award/autoconfirm.js](ke_award/autoconfirm.js))
6. 정시 발사가 **새로고침보다 먼저 재생을 시작**해서, 낡은 화면에서 1단계(그날 새로
   열린 날짜)를 누르고 그 선택이 이어지는 새로고침에 그대로 날아감 → `armForReload()`
   로 예약만 해두고, 새 문서가 뜰 때 recorder 가 스스로 집어가도록 변경
   ([ke_award/recorder.js](ke_award/recorder.js))
7. 문서 파싱이 끝나기 전에 눌러서 **아직 핸들러가 안 붙은 버튼**을 클릭 → 예외도 없이
   아무 일도 안 일어남. `document.readyState === 'loading'` 이면 대기하도록 변경

실제 사이트에서만 재현돼 CDP 로 붙어 잡은 것들은 [ke_award/steps.json](ke_award/steps.json)
의 `cleanup`/`verify` 주석 참고 (shadow DOM 안쪽 버튼, 매일 바뀌는 날짜, 헤더 동명 버튼).
