# 작업 규칙

마일리지가 실제로 빠져나가고, 승부는 매일 09:00 KST 에 10초 안에 끝난다.
한 번 실수하면 다음 기회는 24시간 뒤다. 그래서 추측보다 읽기가 항상 싸다.

## 손대기 전에 읽는 것

| 질문 | 여기에 답이 있다 |
|---|---|
| 어느 버튼/셀렉터/라벨을 누르나 | **ke_award/steps.json** (단계 원본 + cleanup/verify 주석) |
| 사이트가 어떻게 동작하나 (실측치) | **FACTS.md** — 실사이트를 건드리는 작업이면 통째로 읽는다 |
| 지금 무엇을 하고 있나 / 내일 9시 계획 | **NOW.md** |
| 다음에 할 일 / 아직 모르는 것 | **BACKLOG.md** (번호가 곧 ID) |
| 이 함수는 왜 이렇게 생겼나 | 그 함수 위의 주석. 이 저장소는 거기에 적는다 |
| 이 PC 환경 (사내망/크롬 프로필/계정) | 내 메모리 디렉터리 |

## 절대 규칙

1. **셀렉터·라벨·URL 을 추측하지 않는다.** 실사이트를 열기 전에 steps.json 을 읽는다.
   추측 1회는 실사이트 시험 1회를 태우고, 하루에 쓸 수 있는 시험 횟수는 유한하다 —
   과하게 돌리면 사이트가 조회를 거절한다(2026-09-03 실측).
   가장 자주 틀리는 것: 달력의 조회 버튼 라벨은 **"검색"** (steps.json 2단계)이다.
   **"항공편 검색"** 은 조회 화면 위젯의 다른 버튼(`#flight-widget__btn`)이다.

2. **"준비됐다" 는 `dev/rehearse.py` 가 통과를 찍었을 때만 쓴다.** 다른 어떤 것도
   근거가 아니다 — `t.sh` 통과, `preflight` 통과, `morning.ps1 -NoDaily`, 문법 OK,
   코드를 읽어봤음, 전부 아니다. 사용자는 "rehearse 결과 붙여봐" 한 마디로 확인한다.
   붙일 수 없으면 준비된 게 아니다.

   rehearse 는 **크롬을 죽이고 새로 띄운 뒤**(부팅 직후 = 실제 아침 조건) 9시에 도는
   것과 **같은 진입점**으로 **발사까지** 간다. 이 셋 중 하나라도 빠지면 시험이 아니다.

   왜 이렇게까지 하나: 09-04 에 `preflight` 만 통과시키고 "준비 다 됐습니다" 라고
   했다가 09:00 을 통째로 잃었다. 점검기는 재시도를 했지만 정작 발사하는
   autorun/watch_seats 는 한 번 실패하고 죽었다. **관측자를 재고 주자를 안 쟀다.**
   그전 09-03 에는 이미 열린 날짜로 계측기를 재고 "검증 완료" 라고 했다가 실패했다.
   같은 실수다: 진짜 대신 대역을, 실제 상태 대신 편한 상태를 쟀다.

   **"검증됨" 은 09:00 실조건에서만 쓴다.** 그 외에는 "리허설 통과" 라고 쓰고
   무엇이 실전과 달랐는지 한 줄로 같이 적는다. 판단이 서면 `ke-verify` 스킬.

3. **결함을 발견하면 고치거나 BACKLOG 에 번호를 받는다.**
   커밋 메시지에 적는 것은 처리가 아니다. 아는 결함을 그대로 스케줄에 올리지 않는다.

4. **주문·마일리지 안전.** 반복 시험은 `--dry`(7단계 앞 정지, hold 도 안 생김).
   `--pay`/실전 발사는 사용자가 그 날짜를 명시했을 때만. 계측(watch_seats)은 읽기 전용.

   **9222(실전, 와이프 계정)에 파괴적인 작업을 하지 않는다.** 실험은 9223 에서 한다.
   쿠키·프로필·저장소를 지우는 일은 **범위를 좁히고, 지우기 전에 무엇이 지워지는지
   출력해 본다.** 09-04 에 `clear_cookies()` 를 필터 없이 불러 9222 의 네이버 세션
   (`NID_AUT`/`NID_SES`)까지 날렸고, 사람이 직접 로그인해야만 복구됐다.

   **코드를 중첩 문자열로 생성하지 않는다.** 파이썬 heredoc 안에서 파이썬/JS 를
   써서 파일에 쓰면 `\n` 이스케이프가 한 겹 더 벗겨져 파일이 깨진다. 09-04 에만
   세 번 그랬다. 파일 수정은 Edit/Write 로 직접 한다.

5. **재진단 금지.** 아래는 원인이 이미 밝혀져 있다. 다시 파헤치지 말고 확인만 한다.
   - Playwright/CDP 가 멈춤·타임아웃 → `check-loopback.cmd` 의 `[2] CONNECT`.
     FAIL 이면 사외망이다(메모리 참고). 사내망/VPN 이면 풀린다. 그 이상 파지 않는다.
   - 크롬이 두 개(9222/9223) → 어느 것이 무엇인지는 메모리에 적혀 있다.
   - 12단계에서 [아래로 스크롤] 을 못 찾음 → 창 폭. 1400px 이상으로.

6. **세션을 끝내기 전에 `ke-wrap` 스킬.** 새로 잰 사실은 FACTS.md 로, 오늘 한 일과
   내일 계획은 NOW.md 로 넘긴다. 대화창에만 남은 사실은 다음 세션에 없는 사실이다.

## 자주 쓰는 것

    ./t.sh                # 브라우저 없는 검사 (~10초)
    ./t.sh --gate         # 푸시 직전, 9시 결과에 직결되는 것만 (~3분)
    ./t.sh --all          # 전체 (~15분)
    dev/day.ps1           # 다음 09:00 에 무엇을 잴 것인가 - 노선은 여기 한 줄에서만 정한다
    dev/rehearse.py       # 차가운 크롬 -> 발사까지. '준비됐다' 의 유일한 근거
    dev/precheck.ps1      # 전날 16:00 (스케줄 ke_precheck) - rehearse 를 돌리고 실패하면 팝업
    dev/morning.ps1       # 아침 (스케줄 ke_morning 08:20) - 리허설 -> 실전셋팅 -> 08:50 확인 -> 발사
    dev/browsers.ps1      # 크롬 2개 (9222 실전 / 9223 계측)

점검은 **전날 16:00**에 한다. 아침에 문제를 알아봐야 고칠 시간이 없다.
아침은 **08:20** 에 시작해 리허설부터 한다. 로그인 경로는 아침에만 밟기 때문이다.
